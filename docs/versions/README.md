# S3 Explorer 版本记录

本目录按应用实际写入的版本号记录每个小版本。`v0.2.1` 之前的提交没有统一的程序集版本，因此作为“早期原型”保留在 Git 历史中，不补造版本号。

`v0.5.1` 是仓库建立自动发布链后的首个正式 GitHub Release。`v0.2.1`–`v0.5.0` 没有对应 Git tag，其日期和关联变更由 `Directory.Build.props` 与提交历史回填。后续发布由 `vX.Y.Z` tag 驱动，版本记录应在 tag 前完成。

当前已经合入 `main`、但尚未属于任何正式 tag 的变化统一记录在 [`Next / Unreleased`](next.md)。`next.md` 不是版本，也不表示已经发布；正式版本文档一旦随 tag 发布，就作为历史快照保留，不再用后续修复回写旧版本行为。

发布新版本时，以 `next.md` 为输入整理新的 `vX.Y.Z.md`，确认条目完整后在同一发布提交中把 `next.md` 重置为未发布模板。

## 每个版本的维护规则

- 未发布变化先进入 `next.md`；内部重构仅在会影响维护、兼容或运维判断时记录。
- 已带正式 tag 的 `vX.Y.Z.md` 是不可回写的历史快照；发布后修复记录到新的 `next.md`，而不是修改旧版本事实。
- “已交付”只写已经进入该版本代码的行为，“后续计划”只链接路线图。
- 没有 tag 的回填版本标明关联提交，不使用“已发布到 GitHub”措辞。
- 测试数量只在有可复核结果时记录；否则记录测试范围，不猜测数字。
- 兼容性变化、数据格式变化、危险操作和已知限制必须单独列出。
