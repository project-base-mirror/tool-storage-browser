# S3 Explorer v0.6.10

- 日期：2026-07-30
- 状态：发布准备
- 主题：传输、安装与交付稳定性第二阶段

## 真实传输队列回归

- 本地 MinIO 门禁新增真实持久队列场景：运行中暂停、取消、关闭并重建队列、继续传输和最终对象校验。
- 下载断点带远端长度、ETag 与 VersionId；远端对象被替换后重新执行会丢弃旧临时内容，从新对象起点下载，不拼接两个版本。
- 暂停保留可验证断点；取消不留下可见远端对象；重启后的暂停状态从 `transfers.json` 恢复，必须由用户继续。
- MinIO 容器继续使用固定 digest 和唯一名称；也可显式连接本地真实 MinIO，测试不会修改非本次创建的 Bucket。

## 故障注入与恢复边界

- 对网络超时、HTTP 500、连接重置和磁盘写失败增加确定性故障注入。
- 超时、服务端 5xx 与连接中断分类为可重试；普通磁盘 I/O 错误分类为本地错误且不自动重试，避免反复写坏目标盘。
- 用户主动暂停/取消仍走独立取消路径，不会被误判为网络超时。
- 队列的失败分类、尝试次数与最终状态均由自动化测试断言。

## 安装器生命周期

- 新增手动触发的 Windows Installer 生命周期工作流，分别验证 self-contained 与 framework-dependent MSI。
- 生命周期包含安装上一版本、GUI/CLI 启动、覆盖升级到当前版本、再次启动、卸载，以及安装目录和注册表清理。
- MSI 写入安装类型和安装位置标记；客户端检查更新时可据此保持原安装模式。
- 生命周期工作流不会在 PR 或 `main` 推送时自动运行，避免高频开发产生慢速反馈；正式需要时手动执行。

## 可重复构建与重点覆盖率

- `global.json` 固定 .NET SDK 10.0.302，并允许同一功能带的最新补丁；全部项目提交 `packages.lock.json`。
- 本地构建、发布和工作流使用 `--locked-mode`，依赖漂移会在编译前失败。
- 引入 Cobertura 覆盖率采集，但只对耐久 JSON、持久传输队列、文件夹同步计划和持久 CDN 队列设置分组门禁。
- 每组至少 60% 行覆盖且必须匹配到真实生产代码；不使用全项目高百分比掩盖关键路径空白。

## 更新包匹配

- Pages 更新清单升级到 schema 2，同时列出依赖框架/自包含的 ZIP 和 MSI 四种下载。
- MSI 安装版按注册表中的安装类型推荐同类型 MSI，不再跳到便携 ZIP。
- GitHub API 回退和本地缓存保留相同选择；schema 1 旧清单继续兼容。
- 更新窗口明确显示推荐的是安装版还是便携版，以及是否自带 .NET 运行时。

## CDN 指定目标与证书保存

- 对象的“复制 URL、打开、下载测试、预热、刷新”均增加“使用指定 CDN”子菜单，列出当前对象最长前缀匹配的全部启用 CDN，并标记默认项。
- 原有命令继续使用默认 CDN，现有操作习惯不变。
- HTTPS 证书检测成功后立即只写入对应已保存 CDN Profile；不再要求点击“保存全部更改”，也不再触发未保存提示。
- 新增/编辑/复制/删除仍采用配置中心草稿事务；未保存的新地址必须先保存再检测，避免证书结果覆盖旧端点。
- 放弃更改确认改为配置中心拥有的居中窗口，默认选择“否”。

## 兼容性与边界

- Unity Contracts ABI 与 Manifest schema 不变；`AssemblyVersion` 继续为 `1.0.0.0`。
- 更新清单 schema 2 只影响更新下载选择，客户端仍可读取 schema 1。
- 故障注入使用可重复的进程内错误；真实 MinIO 负责验证队列与服务端交互，不伪造云服务故障。
- AWS SSO、AssumeRole、Web Identity 与账户分组顺延到 v0.6.11。
