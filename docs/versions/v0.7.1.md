# S3 Explorer v0.7.1

- 日期：2026-08-04
- 状态：正式发布
- 主题：对象元数据与发布 Header 规则

## 对象 Header、Metadata 与 Tags

- 对象属性页显示并编辑 Content-Type、Cache-Control、Content-Encoding、Content-Disposition、Expires 和自定义 Metadata。
- Metadata 保存采用服务端原地 Copy，并保留对象 Tags；版本化 Bucket 会生成新版本，批量对话框在执行前明确显示请求成本和 Provider Copy 风险。
- Tags 页按需读取，支持保存和删除，遵守对象最多 10 个 Tag、Key/Value 长度、重复 Key 与 `aws:` 保留前缀限制。
- 普通上传与 Multipart 上传使用同一组 Header、Metadata 与 Tags；带自定义属性的旧 Multipart checkpoint 会安全重启，避免把未知属性的旧分片拼入新对象。
- Amazon S3、MinIO 和经过真实验证的阿里 OSS 开放写入；其他尚未验证的兼容 Provider 在本地禁用对象 Tagging 与原地 Metadata 重写。
- 超过 5 GiB 的对象不执行单次原地 Metadata Copy，避免形成不完整或错误的超大对象重写。

## Unity / CLI 发布规则

- `upload` 与 `publish` 增加 `--header-rules <json-file>`，支持默认值和有序 glob overlay。
- 规则覆盖 Content-Type、Cache-Control、Content-Encoding、Content-Disposition、Expires、自定义 Metadata 与 Object Tags。
- Manifest 升级到 Schema 2，逐文件保存最终生效的对象属性；增量计划同时比较 Size、SHA-256 和对象属性，因此只改缓存策略也会重新上传。
- CLI 继续读取 Schema 1 Manifest，Contract API 保持 1，Contracts ABI 仍固定为 `1.0.0.0`。
- `publish-manifest.json` 本身使用 `application/json` 与 `no-cache`，避免 CDN 长时间保留旧发布状态。

## 兼容性与升级

- 需要解析 Schema 2 新字段的 Unity 工具应更新本版本 Contracts DLL；只调用 CLI 并读取 `PublishResult` 的旧集成仍可按 Contract API 1 协商。
- Metadata 原地替换可能产生一次 Copy 请求、对象新版本与相应存储成本；批量执行失败时保留已成功对象并逐项报告，不伪装事务回滚。
- 本版本不包含存储类型专用变更、高级预签名 URL 参数或静态网站配置，这些能力留待后续 v0.7.x。
