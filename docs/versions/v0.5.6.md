# S3 Explorer v0.5.6

- 日期：2026-07-28
- 状态：正式发布
- 主题：AWS 外部凭据来源

## 已交付

### 显式凭据模型

- 连接新增明确的凭据来源，不再把空 Access Key 同时解释为缺少凭据和外部身份。
- 支持已保存密钥、AWS shared credentials/config 指定 Profile、环境变量、容器角色、EC2 实例角色和 AWS SDK 默认链。
- 除默认链外，每种来源都会锁定解析路径；缺少配置时直接给出可操作诊断，不静默回退到其他身份。
- S3-compatible、Google XML API 和其他非 Amazon Provider 只允许已保存密钥，不会意外读取开发机或服务器的 AWS 默认身份。

### 统一运行时与入口

- GUI、CLI、连接测试和所有 S3 运行时操作共用 `AwsCredentialResolver`。
- 连接测试返回实际采用的来源；账户树提示和连接摘要显示来源但不显示密钥值。
- 账户窗口根据来源显示 shared Profile 或密钥字段，环境与角色来源不会显示无意义的 Access/Secret 输入框。
- CLI `profile add` 新增 `--credential-source` 与 `--aws-profile`，列表、详情和连接测试 JSON 同步返回来源。

### 持久化与迁移

- `profiles.json` 升级为 schema 3；外部来源只保存枚举和可选 Profile 名称，Access Key 与 DPAPI 密文字段保持为空。
- `.s3connections` 升级为格式 2，并继续导入格式 1；外部来源引用会迁移，但解析后的环境/角色凭据永远不会进入连接包。
- 含凭据导出仍只处理用户明确保存的密钥，不能借此导出主机或工作负载身份。

## 安全与数据边界

- Profile 名称被视为非敏感配置；Access Key、Secret Key、Session Token 和角色会话不写入日志或普通连接包。
- 容器角色缺少 `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`/`AWS_CONTAINER_CREDENTIALS_FULL_URI`、实例元数据被禁用、环境变量不完整和 Profile 缺失均有单独错误。
- AWS SSO、AssumeRole 与 Web Identity 的令牌缓存不在本版本范围；解析到这些类型时明确拒绝，等待 v0.6.3 的独立会话设计。

## 兼容性与升级

- v0.5.5 及更早 `profiles.json` 未包含来源字段，会按“已保存密钥”读取，不需要手工迁移。
- 新版连接包格式 2 可读取旧格式 1；旧版客户端不会读取格式 2，跨版本迁移时应先升级目标客户端。
- 同步任务和传输队列仍按连接 ID 引用账户，凭据来源切换不会改变连接 ID。

## 验证

- Core 126 项、CDN Infrastructure 8 项、S3 Infrastructure 48 项、App 26 项，共 208 项测试通过。
- 覆盖来源锁定、默认链实际来源识别、缺失 Profile/环境/容器端点诊断、高级令牌拒绝和 S3-compatible 隔离。
- 覆盖 profile schema 3、连接包格式 2、旧格式兼容与外部凭据不落盘。
- 12pt/最小窗口布局和真实 WinForms 运行验证凭据来源切换及字段显隐。
- Release 构建、CLI 隔离数据目录、UI 冒烟、发布包结构和依赖漏洞审计通过。

## 已知限制

- EC2 Instance Metadata 的网络可达性只能在实际请求时验证；客户端会显示锁定来源和 AWS SDK 返回的失败原因。
- 默认链身份可能随进程环境变化；需要稳定身份时应选择 shared profile、环境、容器或实例等明确来源。
- SSO、AssumeRole、Web Identity、账户分组和代理仍属于 v0.6.3 或后续版本。
