# S3 Explorer v0.8.9

发布准备日期：2026-11-06。正式发布状态以对应 GitHub tag、Release 和 Actions 成功记录为准。

## 上传兼容与冲突处理

- 恢复兼容 S3 服务的普通非覆盖上传。Amazon S3、MinIO 和 R2 单次上传继续使用已支持的服务端条件写入；其他服务或上传方式先检查目标是否存在，分片上传在完成前再次检查，不再仅因缺少原子条件写入能力而阻止上传。
- 上传、下载和本地文件剪贴板导入不再预先询问冲突策略；只在目标已存在或被活动队列任务占用时显示冲突选项。普通已存在目标支持覆盖、跳过或自动重命名；队列占用目标不允许覆盖。
- 失败任务释放目标，后续新任务可以使用该路径。重试或恢复旧任务前重新检查目标占用，避免与新任务同时写入，也不会静默改变续传检查点绑定的目标。
- 同一批次中已经完成的任务仍参与目标去重，保留批量路径冲突保护。

## 兼容性与安全边界

- 不改变统一配置 Schema 2、连接包格式 6 或 Contracts ABI，无需迁移已有配置。
- 兼容服务的存在性检查与实际写入之间存在并发窗口，不保证原子非覆盖。需要严格防止并发覆盖时，应使用具备可靠条件写入能力的服务和上传方式。
- 按原 ETag 保存本地编辑仍要求可靠的条件写入；本次放宽普通上传，不放宽编辑保存、条件复制或条件删除的安全要求。目标检查出现权限或网络错误时仍会失败，不把未知状态视为不存在。
- 失败任务恢复时如果目标已被新任务占用，会保留失败状态并报告冲突，需先处理新任务或重新选择目标。

## 发布维护

- 增加显式手动 annotated tag 准备入口，限定已通过 main CI 的精确提交，校验版本清单并拒绝覆盖已有 tag；正常已有 tag 发布路径保持不变，不保存新凭据。

## 验证

- 新增兼容上传协议回归、失败目标释放及恢复冲突回归、WinForms 按需冲突交互测试，并更新文件剪贴板与既有交互测试。
- 发布分支和合并后的 main 须重新通过 Validate：锁定依赖恢复、Release 零警告构建、完整默认测试、真实 Explorer Shell 文件剪贴板、隔离 MinIO 集成与重点覆盖率门禁。
- 正式 tag 工作流再次执行版本清单校验、锁定恢复、测试、覆盖率、打包、包结构、隔离 GUI Smoke，以及远端资产 SHA-256 digest 和下载 CLI 版本检查；Pages 在 Release 验收成功后部署。
- 大型 MSI 和 self-contained ZIP 按仓库规则以 GitHub digest 对照 SHA256SUMS.txt 验收，不重复下载大资产。

## 已知限制

- 云端 Windows runner 的自动测试不等同于实体 Windows 10/11 验收；本次没有使用用户电脑、用户存储凭据或真实 AWS、R2、托管 Supabase 账户进行端到端测试。
- 非原子兼容上传的并发窗口不能通过单客户端检查完全消除。其他限制沿用 [v0.8.8](v0.8.8.md)。
