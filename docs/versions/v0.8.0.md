# S3 Explorer v0.8.0

- 日期：2026-08-17
- 状态：正式发布
- 主题：统一凭据中心与权限检查

## 统一配置与 Credential Vault

- 对象存储、AWS AssumeRole External ID 与 CDN 凭据统一进入 Credential Vault；连接和 CDN Profile 只保存稳定的凭据引用，不再各自复制秘密。
- 桌面端和 CLI 只使用 `%APPDATA%\S3Explorer\configuration.json` 这一份规范配置。文件由 `DurableJsonFile` 原子替换，秘密值统一使用 Windows DPAPI CurrentUser 加密。
- 首次启动会一次性迁移旧 `profiles.json`、`cdn-config.json` 与 `cdn-credentials.json`，成功提交统一配置后将旧文件移入 `legacy-archive`；运行时不再回读或双写旧格式。
- 新增桌面端“配置与凭据中心”和 CLI `credential list/add/update/delete/test` 工作流；删除仍被连接或 CDN Profile 引用的凭据会被阻止。

## 权限检查与安全边界

- 对象存储权限检查按实际 Bucket、Prefix 和目标操作返回逐项报告，区分通过、拒绝、不支持、跳过与无法确定，不再把 `ListBuckets` 的单一结果等同于完整发布权限。
- 默认检查无副作用；需要验证 Put/Delete 的真实写入探针必须显式提供 `--probe-write --yes`，并只在目标 Prefix 内使用受控临时对象。
- 凭据结果只显示安全身份摘要、来源、作用域、Provider 错误码和 Request ID，不回显 AccessKey Secret、Session Token、Bearer Token 或自定义 Header Secret。

## Alibaba Cloud CDN

- 新增 Alibaba Cloud CDN 原生 Provider；同一 Alibaba AccessKey 凭据可以按兼容类型同时关联 OSS 连接与 CDN Profile，无需重复保存。
- 刷新与预热通过 Alibaba Cloud CDN 正式控制面 API 执行；无副作用权限检查使用精确域名查询，并保留 Provider Request ID 便于诊断。
- 通用 HTTP CDN 继续支持 Bearer Token 与自定义 Header，但普通响应无法证明服务端实际校验认证信息，因此会明确报告“无法确定”，不会伪装为权限已确认。

## 连接包与兼容性

- 连接包升级到 v4，以统一凭据引用表达对象存储和 CDN 配置；v1-v3 连接包仍可导入，并在导入事务中迁移到统一凭据。
- 含凭据连接包继续使用迁移密码加密，不复制本机 DPAPI 密文；导入目标机重新使用当前 Windows 用户的 DPAPI 保护。
- 首次迁移前必须退出旧版桌面程序和旧版 CLI，避免旧版本在迁移后继续写入已经归档的旧文件。新版本不保留旧、新配置双运行路径。
- Contract API 保持 1、Manifest Schema 保持 2、Contracts ABI 保持 `1.0.0.0`；现有 Unity 发布协商不因产品主版本变化而失效。

## 已知限制

- Alibaba CDN 的无副作用检查只能证明凭据可执行精确域名查询，不能无副作用地证明刷新或预热写权限；实际写操作仍以控制面 API 结果为准。
- Generic HTTP Provider 无法通用枚举服务端权限，也无法确定服务端是否实际校验 Bearer Token 或自定义 Header。
- 统一凭据受 DPAPI CurrentUser 约束；跨 Windows 用户或跨机器迁移必须使用带迁移密码的连接包，不能直接复制 `configuration.json`。
