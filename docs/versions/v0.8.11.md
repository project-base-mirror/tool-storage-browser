# S3 Explorer v0.8.11

发布准备日期：2026-11-07。正式发布状态以对应 GitHub tag、Release 和 Actions 成功记录为准。

## 旧版应用内升级修复

- 修复 v0.8.8 引入的安装目录参数回归：旧更新器会把原安装目录改为末尾带 `\.` 的路径，导致目标 MSI 在 `CostFinalize` 阶段报错 1324，最后返回 1603。
- 新 MSI 在目录校验前识别与注册安装位置完全对应的旧式参数，恢复原安装目录；默认目录和带空格、中文的自定义目录均纳入升级回归。正常显式安装路径不会被此兼容逻辑覆盖。
- 修复新更新器的 MSI 参数序列化，使用 `APPLICATIONFOLDER="目录"`，不再追加点目录，也不把整个属性赋值作为带引号的参数。
- 此次修复同时覆盖目标安装包和新更新器，不依赖先安装新版更新器才能升级。v0.8.10 仅修更新器自身，不能修复旧版进程已经传给安装包的参数。
- 保留升级事务回滚、SHA-256 复验和管理员确认；允许同版本安装类型切换，避免两类安装包并存。

## 编辑、复制与配置恢复

- 恢复受支持对象的文本编辑和原地、批量 Header / Metadata 编辑，保留冲突检测、已知保护属性和未知结果提示。
- 为 OSS、COS、B2、GCS、Supabase 提供各自适用的 Metadata 保存路径；服务商协议、加密、版本、WORM 和 ACL 限制仍适用，详见[专用服务商说明](../Metadata-Provider-Expansion-2026-11-07.md)。
- 修复文本压缩编码往返、标签与 Metadata 空白保留，避免上传明文却沿用压缩 Header。
- CDN 链接保持原始对象 Key，不静默归一化反斜杠、重复斜杠和开头斜杠；无法由浏览器无损表达的点路径段明确拒绝。
- 完善配置文件跨进程锁、损坏配置恢复、旧配置归档失败处理，以及复制、同步的安全检查与报告。

## 兼容性与验证边界

- 连接配置和 Contracts ABI 不变；跨连接队列仍使用 v2。回退旧版前应完成并清除跨连接任务。
- Windows 生命周期工作流从固定历史源码构建旧更新器，在默认目录和中文自定义目录执行旧更新器到新 MSI 的实际链路，并验证升级后的安装位置和应用启动；这不等同于所有历史版本的数据迁移验收。
- 发布前检查以当前提交的 Validate、Installer lifecycle 和正式 Release 工作流结果为准。测试、构建、覆盖率、包结构、隔离 GUI Smoke 和资产 digest 检查不得以旧提交结果替代。
- 没有使用用户的生产存储凭据，也没有对真实 OSS/COS/B2/GCS/Supabase 账户写入验收；模拟协议测试不等同线上厂商实测。
- 大型 MSI 和 self-contained ZIP 使用 GitHub SHA-256 digest 对照 `SHA256SUMS.txt`，不重复下载大资产。
