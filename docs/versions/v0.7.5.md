# S3 Explorer v0.7.5

- 日期：2026-08-08
- 状态：正式发布
- 主题：Mirror 发布、队列加固与 Provider 能力注册表

## 发布 Mirror

- `publish` 新增显式 `--delete-mode none|mirror`；默认 `none` 完全保持原有只增量上传、不删除远端对象的行为。
- `mirror` 只扫描并删除非空安全 Prefix 内、本地已不存在的远端对象；Prefix 外对象、目录标记和旧 `publish-manifest.json` 均不会进入删除计划。
- 事务顺序固定为上传 → SHA-256 回读校验 → ACL → 删除远端孤儿 → 发布新 Manifest → CDN 后处理。上传、校验、ACL 或删除任一步失败，都不会发布新 Manifest。
- `--dry-run` 同时输出上传与删除计划；结构化 `PublishResult` 增加删除模式、文件数和字节数。阿里 OSS 继续使用已验证的单对象删除兼容路径。

## 队列与 CLI 边界

- 传输队列的“取消全部”不再覆盖历史失败和 Multipart 清理待处理状态；重试、恢复和中断边界新增状态机回归测试。
- CDN 队列手动重试会重置单次尝试字段；终态取消保持幂等，Dispose 时运行中任务持久化为待处理，便于下次启动恢复。
- CLI 连接测试处理器从入口文件拆出，输出包装与命令执行职责分离，并补齐成功、失败和 Verb 回归测试。

## Provider 能力注册表

- Bucket 与对象能力统一由 `S3ProviderCapabilityRegistry` 提供，覆盖 ACL、Policy、CORS、Versioning、Lifecycle、Encryption、Tags、Logging、Object Lock、Ownership、Public Access Block、Presigned URL 和 Version Operations。
- 能力模型区分“不支持 / 只读 / 可读写”；AWS Bucket Object Lock 在当前客户端显示为只读，对象 Retention 与 Legal Hold 仍按可写能力管理。
- GUI 菜单、属性页和 Bucket 配置页共享同一能力与原因；Infrastructure 在发起网络请求前执行相同门禁，CLI 自动继承该边界。
- Amazon S3、MinIO 和已实测的阿里 OSS 能力保持明确条目；其他兼容 Provider 默认保守关闭未经持续验证的写操作。
