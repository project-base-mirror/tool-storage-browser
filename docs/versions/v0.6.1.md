# S3 Explorer v0.6.1

- 日期：2026-07-28
- 状态：开发完成，待发布
- 主题：对象版本浏览、恢复与永久清理

## 已实现

### 分页版本浏览

- “查看 → 显示版本”可浏览当前路径；对象菜单和右键菜单可直接打开单个对象的版本记录。
- 版本窗口显示对象 Key、类型、Version ID、是否当前版本、大小、修改时间与存储类型。
- 使用 S3 的 Key Marker 与 Version ID Marker 分页，每页最多 500 项；服务端返回无效下一页游标时停止并报错，避免重复页死循环。

### 指定版本操作

- 指定版本下载复用原有持久传输队列，任务单独保存 Version ID，断点身份校验仍比较 ETag 与 Version ID。
- 恢复历史版本只把同一个 Key 的明确 Version ID 复制成新当前版本；超过 5 GiB 时继续使用 Multipart Copy，并为每个 Copy Part 指定源版本。
- 单版本和 Delete Marker 永久删除要求两次确认；批量清理只删除扫描到的 Delete Marker 标识，不碰普通历史版本。
- 普通对象删除会先读取 Bucket 版本状态，并明确说明是否会创建 Delete Marker；读取失败时保留保守警告并写入日志。

### CLI

- `object versions` 输出 Version ID、当前状态、Delete Marker 以及下一页两个游标。
- `object download --version-id` 下载指定版本。
- `object restore-version`、`object delete-version` 和 `object clean-delete-markers` 都要求 `--yes`。
- JSON 输出保留稳定字段，供脚本按 Version ID 执行明确操作。

## 安全与兼容性

- 恢复操作的源 Bucket、目标 Bucket、源 Key 与目标 Key 固定相同，只允许 Version ID 变化。
- 批量永久删除检查 S3 多对象删除响应中的逐项错误，不能把 HTTP 成功误报为全部成功。
- Version ID 会进入本地传输任务文件以支持重启恢复，但不属于凭据；日志和错误仍经过现有脱敏处理。

## 验证

- Core 153 项、S3 Infrastructure 58 项、CDN Infrastructure 15 项、App 43 项，共 269 项测试通过。
- MinIO 集成矩阵覆盖两次写入、历史版本下载、恢复、单版本删除、创建与批量清理 Delete Marker；未配置矩阵时安全跳过。
- 版本窗口大字体布局测试覆盖全部列和操作按钮。

## 已知限制

- 版本浏览目前采用独立窗口，不会把历史版本混入主对象列表和现有文件夹导航。
- v0.6.1 只支持向后翻页；重新读取可返回第一页，尚未增加页码缓存或向前翻页。
