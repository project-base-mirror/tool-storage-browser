# S3 Explorer v0.5.5

- 日期：2026-07-28
- 状态：正式发布
- 主题：更新检查可靠性与同步界面

## 已交付

### 更新检查可靠性

- 新增 Pages `update.json` 静态更新清单，客户端优先读取项目主页，不再把匿名 GitHub Release API 作为唯一通道。
- Pages 清单不可用时回退 GitHub Release API；两个在线通道都失败时读取最后一次成功检查缓存。
- 整个在线检查使用 8 秒总超时；关闭应用会取消仍在进行的更新请求。
- 对 HTTP 403/429 读取 `Retry-After` 或 `X-RateLimit-Reset`，显示可诊断信息，不进行无边界重试。
- 缓存只保存公开版本、说明和 HTTPS 下载地址；自动化模式使用隔离缓存文件。
- Pages 与 Release 工作流共同校验清单版本、tag、Release 页面和版本化下载地址。

### 文件夹同步界面

- 左侧任务区改为可调整分栏，并按照实际客户区宽度动态分配名称与方向列，消除最小窗口下的横向滚动条。
- 源路径和目标路径统一为带图标、标题与省略提示的路径摘要卡。
- 文件比较区域始终保留明确边框；尚未创建任务或尚未分析时不再表现为无边界空白区域。
- 增加 12pt 字体与最小窗口尺寸布局回归，验证任务列表、路径卡和结果区域均保持可用。

## 安全与数据边界

- 更新检查只读取项目 Pages 和 GitHub 的公开发布信息，不上传连接、Bucket、对象路径、日志、凭据或设备标识。
- 客户端不要求 GitHub Token，也不会把任何账户凭据附加到更新请求。
- 更新缓存不包含 S3 或 CDN 配置；下载与安装仍必须由用户确认。

## 兼容性与升级

- `profiles.json`、连接包、同步任务、传输队列和 CDN 配置格式均未变化，可直接覆盖 v0.5.4 升级。
- 新增 `%LOCALAPPDATA%\S3Explorer\update-cache.json`；删除该文件只会清除最后成功更新结果，不影响业务配置。
- GitHub API 兼容通道仍识别 v0.5.2 及更早版本的无版本号下载资产。

## 验证

- Core 123 项、CDN Infrastructure 8 项、S3 Infrastructure 36 项、App 23 项，共 190 项测试通过。
- 更新清单解析、版本一致性、Pages 优先、API 回退、限流和缓存回退均由离线单元测试覆盖。
- 同步窗口在 12pt 字体和最小尺寸下验证分栏、路径卡、结果边框与任务列宽；真实 WinForms 运行检查确认任务列表不再显示横向滚动条。
- Release 构建零警告、零错误；隔离数据目录 UI 冒烟 16/16 通过并生成截图。
- CLI 发布包执行 `help` 与隔离数据目录 `profile list --json` 通过。
- NuGet 漏洞审计覆盖 9 个项目，未发现已知漏洞包。
- 发布包检查确认 framework-dependent 与 self-contained 两个 v0.5.5 ZIP 均包含桌面端和 CLI；本地包大小分别为 1.27 MiB 与 50.17 MiB。

## 已知限制

- v0.5.4 及更早客户端仍只认识 GitHub Release API；升级到 v0.5.5 后才会使用 Pages 与缓存通道。
- 缓存只能说明最近一次成功检查时的版本；在线通道不可用且缓存版本不高于当前版本时，客户端不会声称当前一定是最新版。
- 同步分析结果仍不支持逐项取消、复杂条件排除、快照过期和 JSON/CSV 报告，这些属于后续同步第二阶段。
